# Claude CodeとCrazyrouterで作る個人向けワークフロー

Claude Codeを毎日の作業に組み込むなら、最初に整えたいのは「よく使う指示」を再利用できる形にすることです。毎回ゼロからプロンプトを書くと、出力形式や確認項目がぶれます。会議メモ、週報、リリースノート、問い合わせ返信など、繰り返し発生する作業ほどテンプレート化の効果が出ます。

詳細な連載リポジトリはこちらです: [Claude Code Guide](https://github.com/xujfcn/claude-code-guide?utm_source=zenn&utm_medium=article&utm_campaign=claude_code_guide_daily)

## まずエンドポイントを分ける

Crazyrouterを使う場合、設定で混乱しやすいのがBase URLです。

- Claude Code / Anthropicネイティブクライアント: `https://cn.crazyrouter.com`
- OpenAI互換SDK、HTTPリクエスト、アプリ側実装: `https://cn.crazyrouter.com/v1`

`/v1`を二重に付けると、`/v1/v1/...` のようなパスになり、原因が分かりにくいエラーになります。READMEやチームWikiにも、この2種類を分けて書いておくと安全です。

## テンプレート化する対象

最初から全作業を自動化する必要はありません。まずは構造が安定している作業を選びます。

例:

- 会議議事録
- 週次レポート
- 学習メモ
- プロダクト説明文
- リリースノート
- 社内通知
- FAQ返信

テンプレートには、入力項目、期待する出力構造、確認ルールを入れます。たとえば議事録なら、参加者、議題、決定事項、ToDo、担当者、期限、未確認事項を固定セクションにします。

## 自動化より先にレビュー可能な形へ

AI活用で重要なのは、すぐに完全自動化しないことです。まずテンプレートを手動で何度か使い、出力の品質を確認します。安定してきたら、データ収集や保存だけをスクリプト化する、という順序が現実的です。

週報であれば、タスク管理ツールから完了項目を集め、障害や決定事項を追記し、Claude Codeに週報テンプレートで整形させます。その後、人間が文脈、数値、責任範囲を確認してから共有します。

## 良いテンプレートの条件

良いテンプレートは、細かすぎず、曖昧すぎません。次のようなルールを入れると実務で使いやすくなります。

- 不明な情報は推測せず「未確認」に入れる
- 日付、担当者、数値を捏造しない
- 事実と仮説を分ける
- 技術用語や製品名は維持する
- 人間が確認すべき点を最後に列挙する

これにより、見た目は整っているが信頼できない文書を減らせます。

## テンプレートは資産として管理する

うまく機能したテンプレートはチャット履歴に埋めず、`prompts/` ディレクトリ、チームWiki、社内ドキュメントなどに保存します。Gitで管理すれば、変更履歴、レビュー、ロールバックもできます。

Claude CodeとCrazyrouterの組み合わせは、単なるチャット補助ではなく、繰り返し作業を標準化するための開発者向けワークフローになります。まずは今週何度も行う作業を1つ選び、テンプレートにして、数回使って改善してみてください。
