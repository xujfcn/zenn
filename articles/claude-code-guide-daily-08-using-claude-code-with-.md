# Claude Code と Crazyrouter で文書抽出・整形・一括処理を実用化する

長い議事録、契約書、社内レポート、請求書、設計仕様書を読む作業は、開発チームでも運用チームでも時間を使います。Claude Code を Crazyrouter 経由で利用すると、文書からの情報抽出、要約、表の整理、Markdown 化、一括リネームなどをワークフロー化しやすくなります。

シリーズのリポジトリはこちらです: [claude-code-guide](https://github.com/xujfcn/claude-code-guide?utm_source=zenn&utm_medium=article&utm_campaign=claude_code_guide_daily)

## まず Base URL を分ける

設定で特に間違いやすいのは `/v1` の扱いです。

- Claude Code / Anthropic ネイティブクライアント: `https://cn.crazyrouter.com`
- OpenAI 互換 SDK / HTTP / アプリ側: `https://cn.crazyrouter.com/v1`

Claude Code では次のように設定します。

```bash
export ANTHROPIC_BASE_URL="https://cn.crazyrouter.com"
export ANTHROPIC_API_KEY="your_crazyrouter_api_token"
```

OpenAI 互換 SDK では `base_url` に `https://cn.crazyrouter.com/v1` を指定します。ここを混同すると `/v1/v1/...` のようなリクエストになり、原因調査に時間を使うことがあります。

## 文書から必要な情報を抽出する

「要約して」だけでは、業務で再利用しにくい出力になりがちです。抽出したい対象と形式を明確にします。

例:

> この議事録から確定した決定事項だけを抽出してください。列は「領域、決定内容、担当者、期限、根拠引用」の Markdown 表にしてください。担当者や期限がなければ `未記載` と書いてください。

契約書なら、日付、支払条件、更新条件、責任範囲などを表にできます。重要文書では「不明な項目は推測せず、人間確認と明記する」と入れておくと安全です。

## 表データは抽出と分析を分ける

PDF や Word 内の表は、まず構造を保ったまま取り出し、その後に分析します。

1. 表をそのまま抽出する
2. 抽出結果を確認する
3. 合計、増減、異常値などを分析する

この順序にすると、列ずれや空セルの見落としを減らせます。

## 整形・変換にも使える

Claude Code は、文書の意味を変えずに形式をそろえる用途にも向いています。

- 見出し階層の統一
- 箇条書きと番号リストの整理
- プレーンテキストの Markdown 化
- 表の Markdown 化
- 画像キャプションの不足チェック
- 複数文書のスタイル統一

ポイントは、社内ルールを具体的に書くことです。「H1 は文書タイトル、H2 は章、H3 は節、手順は番号リスト、補足は箇条書き」のように指定します。

## 一括処理は小さく試す

一括リネーム、文言置換、通知文生成、部門別レポート作成は便利ですが、失敗も一括で広がります。実行前に必ずバックアップし、代表ファイルでテストします。

安全な流れは次の通りです。

1. 元ファイルを退避する
2. 1〜2件で試す
3. 出力を人間が確認する
4. 処理ログを出す
5. 残りを分割して処理する
6. 完了後にサンプル確認する

ファイル名変更では、変更前後の対応表と重複時のルールを出させると運用しやすくなります。

## まとめ

Claude Code と Crazyrouter を組み合わせると、文書処理を「その場の依頼」から「再利用できる手順」に近づけられます。大事なのは、抽出対象、出力形式、根拠、未記載時の扱い、検証方法を明示することです。特に契約、請求、法務、顧客向け文書では、最終確認を人間が行う前提で使うのが現実的です。
